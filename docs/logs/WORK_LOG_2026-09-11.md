### 修复 3：Web GUI 默认模型走错 provider（deepseek-official）
- 现象：webview 内发消息报 `MISSING_CREDENTIAL: no API key for provider route "deepseek-official"`。Web GUI 默认模型选择走 `settings.yaml` 的 `agent-default-model` 节，此前 `writeLlmSettings` 只写了 `llm-pi-ai` provider 清单，未写默认路由，UI 回退到内置 DeepSeek 官方路由。
- 修法：`writeLlmSettings()`（src/main/dshRuntime.ts）追加 `agent-default-model: { provider: muyujian-gateway, model: <用户模型> }`。
- 验证：webview 里模型选择器显示「当前 kimi-k3」。

### 修复 4：AI 网关 baseUrl 缺 /v1（Stream ended without finish_reason）
- 现象：默认模型修正后，发消息流式报 `TRANSPORT Stream ended without finish_reason`（重试 5/5 后失败）。
- 根因：用户保存的 `aiConfig.baseUrl` {= https://api.yujianwudi.top}（无 /v1）。dsh 的 openai-completions 适配器直接拼 `<baseURL>/chat/completions`，打到网关网站 SPA 首页（返回 200 HTML），dsh 解析不到 finish_reason。应用自身的问答（`/responses`）同样依赖带 /v1 的 baseUrl。
- 修法：`validateAiBaseUrl()` 在 pathname 为空时自动补 `/v1`；`getModelConfig` 拆出 `getNormalizedAiModelConfig()`（归一化失败返回 null，不写坏 settings.yaml），dshRuntime 与 dshWeb 共用；类型签名放宽为可返回 null。
