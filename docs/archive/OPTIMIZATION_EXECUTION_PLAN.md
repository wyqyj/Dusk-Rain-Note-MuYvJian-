# 暮雨笺优化执行计划

本文件将 `OPTIMIZATION_PLAN.md` 转换为当前仓库可执行、可回归的交付顺序。目标是先建立安全和模块边界，再处理性能问题，避免在缺少验证护栏时进行高风险数据迁移。

## 本轮范围

### 1. 安全加固（P0）

- 为 Markdown、LaTeX 和 Pandoc HTML 统一增加 DOMPurify 消毒，覆盖所有 `dangerouslySetInnerHTML` 渲染入口，并保留协议/样式二次收紧。
- 在所有窗口启用统一的 CSP，限制脚本、资源、连接和 frame 来源。
- 对 `workspace-open-path` 做规范化路径校验，只允许打开当前工作台目录、内置案例目录和内置技能目录中的文件或目录。
- 对 IPC 输入增加最基本的边界校验，避免渲染进程直接把任意路径传入主进程。

### 2. 架构边界（P0/P2）

- 新增 `src/shared` 类型目录，集中维护便签、画布和工作台的领域类型。
- 保持现有行为不变，先将组件和 Store 中重复的核心类型迁移到共享类型；后续再按职责拆分主进程 IPC 和 `StudyWorkbench` 子视图。
- 为 IPC 协议建立可渐进扩展的类型映射，避免一次性重写全部 preload API。

### 3. 低风险性能优化（P1）

- 延长并完善便签保存防抖，增加内存快照和未完成定时器清理，避免重复全量写盘。
- 附件保存增加去重和错误保护；附件文件落盘迁移暂缓，待迁移脚本和回滚方案独立验证后再做。
- 为画布增加基于视口的元素裁剪，保持交互和数据结构不变。
- 编辑器继续即时更新内存状态，但将磁盘写入统一交给 Store 防抖，避免每次击键触发保存。

### 4. 工程化护栏（P2/P4）

- 开启 `noUncheckedIndexedAccess`，修复由此暴露的类型问题。
- 引入 Vitest，先覆盖 Markdown 消毒、任务解析和便签校验等纯函数。
- CI 增加类型检查和单元测试，构建作为最后验收步骤。

## 暂缓项及原因

- 附件 Base64 到独立文件的迁移：涉及现有数据兼容、备份/导入导出和跨窗口读取，需要单独的迁移与回滚测试。
- Markdown Web Worker：KaTeX、DOMPurify 和 Vite Worker 构建链需要单独验证，先用渲染缓存和保存节流降低主线程压力。
- `StudyWorkbench` 全量拆分、主进程 15 文件拆分：先建立共享类型和 IPC 边界，避免在行为未覆盖时做大范围移动。
- 自动更新、代码签名和完整 E2E：依赖发布渠道、签名证书和稳定测试环境，不在本地优化批次中伪造完成。

## 验收标准

1. `npm run build` 通过，主进程和渲染进程均无 TypeScript 错误。
2. 恶意 HTML、脚本协议链接和危险属性不会进入 DOM；合法 Markdown、KaTeX 和 Wiki 链接仍可渲染。
3. 工作台只能打开受信任根目录下的路径，越界路径返回明确失败结果。
4. 便签编辑、画布编辑、附件添加和跨窗口同步行为保持不变。
5. `npm test` 通过，CI 在安装依赖后执行类型检查、单元测试和构建。

## 预期收益

- 安全性：降低笔记内容导致 XSS、脚本协议执行和任意本地路径打开的风险。
- 可维护性：领域类型和 IPC 契约集中后，新增工作台模块只需扩展共享模型，不必在多个组件中复制定义。
- 可扩展性：保存、渲染和视口裁剪形成清晰的基础设施边界，后续接入增量存储、Worker 和虚拟列表时可以替换实现而不改业务界面。
- 性能稳定性：减少重复 JSON 序列化与写盘，元素数量较多时只处理视口附近的画布节点，降低输入卡顿和启动抖动。
- 交付质量：类型检查、纯函数测试和 CI 构建形成最小回归护栏，后续拆分和数据迁移的风险可被及时发现。
